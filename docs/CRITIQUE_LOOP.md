# گزارش داخلی پنج دور نقد و بازنویسی

این سند برای قابلیت ممیزی توسعه نگه‌داری می‌شود؛ خروجی کاربر فقط APK نهایی است.

## دور ۱ — امتیاز ۳/۱۰

نمونهٔ اولیه فقط تغییر ۲۴ساعته را مرتب می‌کرد و آن را خرید/فروش می‌نامید.

ایرادهای سختگیرانه:
- تغییر ۲۴ساعته برای ورود کوتاه‌مدت دیرهنگام و گمراه‌کننده است.
- حجم، روند، کندل بسته‌شده و کیفیت داده لحاظ نشده بود.
- جهش پامپی می‌توانست اشتباهاً «خرید قوی» شود.
- وابستگی به یک API، برنامه را شکننده می‌کرد.

بازنویسی: دریافت OHLCV پنج‌دقیقه، EMA/RSI و تفکیک سیگنال از هشدار حرکت.

## دور ۲ — امتیاز ۵/۱۰

ایرادها:
- RSI و EMA تک‌تایم‌فریم نویز زیادی داشتند.
- حجم با میانگین سنجیده می‌شد و خود جهش، baseline را خراب می‌کرد.
- کندل درحال‌تشکیل وارد تحلیل می‌شد (look-ahead/intrabar bias).
- امتیاز به‌اشتباه شبیه «احتمال موفقیت» نمایش داده می‌شد.

بازنویسی: تایم‌فریم ۱۵دقیقه، استفادهٔ انحصاری از کندل بسته‌شده، میانهٔ حجم و نام‌گذاری «قدرت شواهد».

## دور ۳ — امتیاز ۶٫۵/۱۰

ایرادها:
- آستانهٔ ثابت پامپ/دامپ برای BTC و آلت‌کوین کوچک یکسان بود.
- بازار کم‌نقدشونده هشدارهای جعلی می‌داد.
- قطع یک سرویس کل برنامه را از کار می‌انداخت.
- دادهٔ قدیمی در UI از دادهٔ زنده قابل تشخیص نبود.

بازنویسی: robust z-score با Median/MAD، حداقل حجم دلاری، Binance/KuCoin failover و برچسب cache/timestamp.

## دور ۴ — امتیاز ۸/۱۰

ایرادها:
- روند کاملاً تخت به‌علت مقایسهٔ `>=` رأی صعودی می‌گرفت.
- جهش حجم سه‌کندلی و جهش تک‌کندلی تفکیک نشده بود.
- کاربر دلیل برچسب، ابطال سناریو و محدودیت‌ها را نمی‌دید.
- اسکن بیش‌ازحد می‌توانست rate limit بسازد.

بازنویسی: ناحیهٔ بی‌تفاوتی عددی، حجم تک/سه‌کندلی، صفحهٔ توضیح شفاف، worker pool محدود و بازهٔ اسکن سه‌دقیقه‌ای.

## دور ۵ — امتیاز نهایی ۹/۱۰

بهبودهای نهایی:
- تست‌های رگرسیون برای بازار تخت، روند صعودی/نزولی، pump alert و حذف کندل ناقص.
- فیلتر توکن اهرمی/استیبل و افزودن اجباری منتخب‌ها به دامنهٔ اسکن.
- عدم دریافت کلید API و عدم اجرای سفارش؛ سطح حمله و ریسک مالی کمتر.
- رابط Native سبک، فارسی RTL، حالت بدون شبکه و cache محلی.
- سناریوهای ATR با برچسب صریح «آماری، نه سفارش پیشنهادی».
- Network Security Config با منع cleartext و بدون مجوزهای اضافی.

چرا ۱۰/۱۰ نیست:
- REST polling جای WebSocket را نمی‌گیرد و حرکت‌های بسیار سریع ممکن است از دست بروند.
- API عمومی می‌تواند در بعضی کشورها یا لحظات محدود شود.
- بک‌تست گذشته تضمین آینده نیست و این نسخه عمداً ادعای نرخ برد نمی‌کند.
- اعلان پس‌زمینه اضافه نشده تا بدون سرویس foreground و مصرف باتری، ادعای پایش دائمی ایجاد نشود.

# ممیزی پنج‌مرحله‌ای ارتقای نسخهٔ ۶

## دور ۱ — صحت دادهٔ چندمنبعی

ایراد: میانگین ساده می‌توانست با قیمت خراب یک صرافی منحرف شود و حجم همان منبع نیز رتبه‌بندی را آلوده کند.

بازنویسی: میانهٔ اولیه، حذف منبع با فاصلهٔ بیش از ۸٪، محاسبهٔ دوبارهٔ میانه و جمع‌زدن حجم فقط از منابع پذیرفته‌شده. اختلاف منبع و تعداد منابع اکنون در مدل، cache و UI دیده می‌شود.

## دور ۲ — تاب‌آوری و هم‌زمانی

ایراد: انتخاب «سریع‌ترین API» دادهٔ سه صرافی دیگر را دور می‌ریخت؛ شکست کندل منبع منتخب نیز کل نماد را رد می‌کرد.

بازنویسی: discovery هم‌زمان چهار صرافی با deadline محدود، CoinGecko غیرالزامی، worker pool پنج‌تایی، انتخاب منبع کندل بر اساس حجم و failover تا سه صرافی. انتظار کوتاه بعد از دو پاسخ، برای رسیدن منابع کندتر به ۸ ثانیه افزایش یافت.

## دور ۳ — دامنه و تجربهٔ کاربر

ایراد: فهرست ثابت بازارهای پرحجم، ارز دلخواه کاربر را پوشش نمی‌داد و لمس کارت فقط دیالوگ داخلی را باز می‌کرد.

بازنویسی: ۴۰/۸۰/۱۲۰ بازار، افزودن نماد دلخواه به اسکن گسترده، صف‌کردن درخواست هنگام اسکن فعال، حذف منتخب نامعتبر، لمس کارت برای TradingView و دکمهٔ مستقل جزئیات. عمل Search صفحه‌کلید نیز به تحلیل متصل شد.

## دور ۴ — امنیت، حریم خصوصی و صداقت منبع

ایراد: نسبت‌دادن دادهٔ مستقیم به Google/TradingView/CMC بدون API رسمی، ادعایی نادرست و وابسته به scraping بود.

بازنویسی: فقط API عمومی Binance، KuCoin، Bybit، OKX و CoinGecko مصرف می‌شود؛ سه سرویس دیگر فقط با URL رسمی و اقدام کاربر باز می‌شوند. HTTPS اجباری، پاسخ HTTP محدود، بدون کلید API، حساب، مجوز معامله یا cleartext باقی ماند.

## دور ۵ — رگرسیون و انتشار

کنترل‌ها: compile کامل Java/XML، تست‌های deterministic موتور تحلیل، harness اجماع با قیمت پرت، بررسی نسخه/manifest، ساخت DEX و منابع، امضای همان گواهی v2/v3 و ثبت SHA-256 APK.

محدودیت‌های باقی‌مانده:
- REST polling جای WebSocket نیست و API عمومی ممکن است محدود یا مسدود شود.
- نمادهای هم‌نام در CoinGecko با بهترین رتبه تطبیق داده می‌شوند و metadata صرفاً کمکی است.
- اختلاف قیمت کم نیز ریسک اجرای واقعی، اسلیپیج یا کیفیت دفتر سفارش را حذف نمی‌کند.
- نصب روی سخت‌افزار واقعی در محیط build خودکار قابل اجرا نیست؛ امضای رمزنگاری و ساختار APK جایگزین تست دستگاه نیست.

# ممیزی پنج‌مرحله‌ای هوش مصنوعی نسخهٔ ۷

## دور ۱ — رد «AI نمایشی»

ایراد: افزودن متن تولیدی یا چند شرط `if` با برچسب AI، هوش مصنوعی واقعی نیست و کاربر را گمراه می‌کند.

بازنویسی: مدل supervised رگرسیون لجستیک به‌صورت واقعی برای هر ارز روی ویژگی‌های سری زمانی آموزش می‌بیند. نوع مدل، افق، تعداد نمونه، نتیجهٔ آزمون و رأی آن در UI آشکار است.

## دور ۲ — نشت آینده و بیش‌برازش

ایراد: آموزش و ارزیابی روی یک پنجره یا استانداردسازی با کل داده می‌توانست دقت جعلی بسازد.

بازنویسی: split زمانی، استانداردسازی فقط با train، سه ردیف purge در مرز و validation روی بخش جدیدترِ دیده‌نشده. مدل تک‌کلاسه یا دادهٔ دارای شکاف کافی رد می‌شود.

## دور ۳ — کنترل ادعای احتمال

ایراد: نمایش `p(up)` ممکن است به‌اشتباه احتمال سود یا نرخ برد تعبیر شود.

بازنویسی: در هشدار اولیه، تنظیمات و صفحهٔ جزئیات صریحاً گفته می‌شود درصد خروجی طبقه‌بند است. اعتبار جداگانه، دقت متوازن و تعداد نمونه نمایش داده می‌شوند و عبارت «تضمین» حذف/رد شده است.

## دور ۴ — ایمنی ترکیب با سیگنال

ایراد: مدل کوتاه‌تاریخ می‌توانست اندیکاتورهای پایدار یا هشدار پامپ/دامپ را تحت سلطه بگیرد.

بازنویسی: quality gate شامل balanced accuracy و Brier، ناحیهٔ بی‌تصمیم ۱۲٪، رأی محدود `±12` و اولویت قطعی هشدار جهش/ریزش. اختلاف AI و تکنیکال به‌عنوان احتیاط نمایش داده می‌شود.

## دور ۵ — حریم خصوصی، هزینه و رگرسیون

کنترل‌ها: آموزش/inference بدون شبکهٔ AI و بدون API key، حداکثر ۱۵۰ epoch و ۸ ویژگی، خروجی deterministic، تست رژیم قابل‌یادگیری و رد تاریخچهٔ تک‌کلاسه، تست‌های قبلی اندیکاتور و اجماع، compile، ساخت و امضای APK.

محدودیت‌های باقی‌مانده:
- حدود ۲۵ ساعت کندل ۵دقیقه برای شناخت همهٔ رژیم‌های بازار کافی نیست.
- validation اخیر ممکن است با تغییر رژیم بی‌اعتبار شود؛ به همین علت رأی مدل کوچک است.
- مدل خبر، دادهٔ درون‌زنجیره‌ای، دفتر سفارش یا احساسات شبکه‌های اجتماعی را نمی‌بیند.
- نتیجهٔ AI توصیهٔ شخصی، نرخ برد تضمینی یا مجوز معاملهٔ خودکار نیست.

# پنج دور نقد و بازنویسی سیگنال نسخهٔ ۸

## دور ۱ — حذف اجبار بالا/پایین

ایراد: مدل دودویی حتی در نویز و بازار رنج مجبور بود صعود یا نزول را انتخاب کند.

بازنویسی: دو مدل softmax سه‌کلاسه با کلاس خنثی و برچسب تطبیقی مبتنی بر نوسان. حرکت کوچک‌تر از noise floor دیگر سیگنال جهت‌دار نمی‌سازد.

## دور ۲ — کاهش شانس یک split خوش‌شانس

ایراد: یک holdout می‌توانست کیفیت مدل را بیش‌برآورد کند و مدل آموزش‌دیده فقط بخش قدیمی تاریخچه را ببیند.

بازنویسی: دو fold توسعه‌یابندهٔ walk-forward برای هر افق، purge متناسب با افق، جمع‌کردن پیش‌بینی‌های خارج‌نمونه، کالیبراسیون و سپس refit روی کل تاریخچهٔ برچسب‌دار.

## دور ۳ — تأیید افق و رژیم

ایراد: سیگنال ۱۵دقیقه‌ای ممکن بود با ساختار ۳۰دقیقه یا رژیم ۱۵دقیقه مخالف باشد.

بازنویسی: ensemble افق‌های ۱۵ و ۳۰ دقیقه، امتناع هنگام تضاد، ADX/+DI/-DI برای جهت روند و ATR برای نوسان بسیار بالا. رنج و volatility آستانهٔ بالاتری دارند.

## دور ۴ — کیفیت داده پیش از جهت

ایراد: اندیکاتور قوی روی تک‌منبع، spread زیاد، حجم کم یا تاریخچهٔ ناقص همچنان می‌توانست برچسب قوی بگیرد.

بازنویسی: امتیاز کیفیت مستقل از ۰ تا ۱۰۰. زیر ۶۰ سیگنال جهت‌دار و زیر ۷۵ سیگنال قوی مسدود می‌شود؛ evidence نیز با کیفیت داده تعدیل می‌شود.

## دور ۵ — کنترل خروجی و آزمون تضاد

ایراد: اضافه‌کردن اندیکاتور بیشتر بدون gate می‌توانست فقط سیگنال‌ها را زیاد کند.

بازنویسی: حداقل مستقل برای امتیاز تکنیکال، حداقل جدا برای امتیاز نهایی، مخالفت AI/رژیم به‌عنوان blocker و تأیید AI یا ADX برای برچسب قوی. تست deterministic برای بازار رنج، روند، جهش، دادهٔ کم‌کیفیت، سه کلاس AI، توافق افق و bounds رأی افزوده شد.

چرا هنوز تضمین نیست:
- حدود ۲۵ ساعت تاریخچه همهٔ چرخه‌های بازار را پوشش نمی‌دهد.
- خبر، order book، دادهٔ درون‌زنجیره‌ای و هزینهٔ اجرای واقعی مدل نشده‌اند.
- معیارهای خارج‌نمونه نیز با تغییر رژیم فرسوده می‌شوند.
- هدف نسخهٔ ۸ precision بالاتر با سیگنال کمتر است، نه ادعای نرخ برد ثابت.

# پنج دور نقد و بازنویسی نقشهٔ معامله نسخهٔ ۸.۱

## دور ۱ — پرهیز از ادعای API غیرواقعی

ایراد: deep link عمومی TradingView فقط نماد/interval را باز می‌کند و اپ ثالث نمی‌تواند drawing دلخواه را به حساب یا نمودار رسمی تزریق کند.

بازنویسی: محدودیت صریح در UI و README نمایش داده شد؛ هیچ API خصوصی، scraping یا وعدهٔ ترسیم خودکار در اپ رسمی استفاده نمی‌شود.

## دور ۲ — نمایش فوری بدون وابستگی

ایراد: الزام Pine Editor روی موبایل تجربهٔ ضعیفی دارد و ممکن است در بعضی نسخه‌های اپ در دسترس نباشد.

بازنویسی: `TradePlanChartView` بومی و آفلاین، ۳۲ کندل بسته‌شده را همراه ناحیهٔ ENTRY، STOP و TP1/TP2 داخل جزئیات رسم می‌کند.

## دور ۳ — انتقال دقیق به TradingView

ایراد: کپی دستی اعداد می‌تواند باعث جابه‌جایی رقم یا سطح شود.

بازنویسی: Pine Script نسخهٔ ۵ از همان فیلدهای immutable نتیجه ساخته می‌شود؛ اعداد با Locale ثابت و بدون scientific notation صادر و ناحیهٔ ورود با `fill` مشخص می‌شود.

## دور ۴ — جلوگیری از کهنگی پنهان

ایراد: اسکریپت ثابت ممکن است با اسکن بعدی اشتباهاً زنده تلقی شود.

بازنویسی: timestamp کندل در comment خروجی ثبت، STATIC در label نوشته و در رابط تأکید شد پس از هر اسکن باید خروجی دوباره ساخته شود.

## دور ۵ — ایمنی و آزمون

ایراد: سطح‌ها ممکن است به‌عنوان سفارش قطعی یا تضمین سود برداشت شوند.

بازنویسی: واژهٔ «سناریوی آماری»، هشدار NOT FINANCIAL ADVICE، برچسب ابطال به‌جای دستور stop و توضیح عدم اجرای سفارش حفظ شد. تست deterministic برای symbol sanitization، اعداد بسیار کوچک، جهت سناریو و وجود همهٔ خطوط افزوده شد.
